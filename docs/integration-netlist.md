# План доработки: интеграция pinout-asyncapi с pinout-netlist (эпик E0)

Цель — привести вывод async-валидатора к [общему формату отчёта экосистемы](../../pinout-openapi/docs/report-format.md), чтобы его потреблял [`pinout-netlist`](../../pinout-netlist). Код валидации не меняем — только слой отчёта.

Концепт: [../../pinout/README.md](../../pinout/README.md). Бэклог экосистемы: [E0](../../pinout/backlog.md).

## Что есть сейчас

- Валидатор отдаёт результат через CLI (текст) и `compatibility_report.json` (свой формат, см. `contract-tests.yaml` → `settings.json_report_file`).
- Есть типизированный `ValidationError` (код, message, location, context) — уже близок к канону.

## Что меняем

1. **Маппинг в общий формат.** Существующий результат валидации → структура канона:
   - `validator: "pinout-asyncapi"`, `interaction: "async"`, `schema_version` из канона.
   - `consumer`/`provider`: name + spec_ref (+ version, если известен коммит).
   - `verdicts[].subject` = имя канала/операции потребителя (async-форма `subject`).
   - `verdicts[].errors[]` = текущие `ValidationError` (формат совпадает 1:1).
   - `compatible` = AND по verdicts; `generated_at` проставляется при выгрузке (RFC3339).
2. **Выгрузка.** Команда/флаг отдачи отчёта в общем формате (stdout и/или файл) — не ломая текущий CLI и exit codes.
3. **Обратная совместимость.** Старый `compatibility_report.json` либо сохраняется как есть, либо переключается флагом; данные при маппинге не теряются.

## Чего НЕ делаем

- Не меняем алгоритм валидации каналов/сообщений.
- Не тащим в async зависимость от netlist — только формат на выходе (netlist сам забирает/принимает).

## Тикеты

- [ ] E0.1 — структура отчёта канона + маппер из результата валидации (юнит-тесты маппера).
- [ ] E0.2 — выгрузка отчёта (stdout/файл), флаг формата; сохранить exit codes.
- [ ] E0.3 — компонентный тест: совместимая и несовместимая пары → корректный отчёт канона.
- [ ] E0.4 — отметить в README async раздел «формат отчёта» со ссылкой на канон.

## DoD

- async-валидатор отдаёт отчёт в [общем формате](../../pinout-openapi/docs/report-format.md); `schema_version` совпадает с pinout-openapi.
- Текущий CLI и exit codes не сломаны; зелёный CI.
- Маппинг покрыт тестами; данные не теряются.

## Зависимость по порядку

Канон формата определён в `pinout-openapi` (решение оператора). E0 выполняется после фиксации канона (готов) и согласованно с E1, чтобы оба валидатора давали идентичную структуру (различается только `subject`).
